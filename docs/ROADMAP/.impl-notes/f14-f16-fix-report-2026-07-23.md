## Semantic notes on F16-1 (compat vs strict rename)
Everywhere's `memory_snapshot` is a write verb (`(site, cmd, content)`); openclicky's pre-fix `memorySnapshot()` was a read verb returning `MemorySnapshot` and is dispatched from `OpenClickyExternalControlBridge.swift:2789`. The bridge is out of scope for this fix. The reconciliation therefore:

- Adds `memorySnapshotWrite(cmd:content:)` implementing the Everywhere semantic verbatim (per-cmd rotation of the 5 newest, `yyyyMMddTHHmmssZ` UTC stamp, silent rotation errors mirroring `MemoryStore.cs:210-213`).
- Keeps `memorySnapshot()` as an openclicky superset read verb with a doc-comment header calling out the Everywhere inversion so future bridge wiring can plug in the write path under whatever wire name the roadmap decides on.

This gives a future bridge PR a clean handle: either alias `memory_snapshot` -> `memorySnapshotWrite` and add a fresh read tool (`memory_dump`), or split into `memory_snapshot_write` / `memory_snapshot_read`. Neither choice needs any further changes inside the SPM package.
