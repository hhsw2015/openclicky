## CRITICAL #1 — F32/F34 return payload missing MCP text-envelope wrapper

Before: `chat_send` and `chat_subscribe` returned a raw `[String: Any]` dict directly from `execute` (`OpenClickyChatBusTools.swift:135-140, 169`). `web_search` / `web_fetch_url` did the same (`OpenClickyWebBridgeTools.swift:95-99, 120-128, 145-151`). `executeSensorTool` placed that dict verbatim into `result.content[]` — MCP schema-invalid, because peer families (Connector, OpenCLI, OpenDia, adapter, page, capture) all return `{type:"text", text:"<json>"}`.

After: every return goes through a `textEnvelope(from:)` helper that mirrors the pattern in `OpenClickyOpenCLIBridgeTools.swift:222-226` — `JSONSerialization` -> UTF-8 string -> `["type":"text", "text": jsonText]`.

- `Packages/.../OpenClickyChatBusTools.swift:108-171` (dispatch, handleSend, handleSubscribe) — all four return sites wrapped.
- `Packages/.../OpenClickyChatBusTools.swift:184-207` — `failBody(code:message:)` + `textEnvelope(from:)` helpers.
- `cursor-buddy/OpenClickyWebBridgeTools.swift:68-141` — `execute`, `handleSearch`, `handleFetch`: every success path AND every error path wrapped.
- `cursor-buddy/OpenClickyWebBridgeTools.swift:146-171` — `failBody(code:message:)` + `textEnvelope(from:)` helpers.

Rationale: peer bridges' shape is the authoritative contract for MCP clients pinning against `result.content[0].text`. F32/F34 were the only two families out of eight producing the shape the reviewer flagged.

## CRITICAL #2 — F35 ExtractionRulesStore.upsert re-entrant NSLock deadlock

Before (`OpenClickyPageBridgeTools.swift:438-458`): `upsert` acquired `lock.lock()` then called `loadUnsafe`, which ALSO acquired `lock.lock()`. `NSLock` is non-reentrant on the same thread — the second `lock()` blocked permanently. Any single `page_save_extraction_rule` call hung.

After (`OpenClickyPageBridgeTools.swift:405-489`):

- `loadUnsafe` -> renamed to `loadLocked` (caller MUST hold the lock).
- `save` -> renamed to `saveLocked` for symmetry.
- `upsert` acquires the lock ONCE, then calls `loadLocked` / `saveLocked` directly.
- `match` now takes the lock ONCE at entry (previously deferred to `loadUnsafe`).
- Class comment added: "NSLock is not reentrant; internal methods suffixed `Locked` assume the caller holds the lock and MUST NOT re-lock."

Regression: `cursor-buddyTests/OpenClickyF32ThroughF36BridgeFixTests.swift:test_extraction_rules_upsert_does_not_deadlock` calls `upsert` inside an XCTestExpectation with a 2-second timeout. A regression would time out; the current impl finishes in ~ms.

Verified: no method in `ExtractionRulesStore` calls another lock-taking method from within its own critical section.
