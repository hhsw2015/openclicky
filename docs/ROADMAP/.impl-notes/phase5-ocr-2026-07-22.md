## Semantics extracted

Everywhere signature:

```csharp
IReadOnlyList<OcrLine> Recognize(
    Stream pngStream,
    PixelPoint originPx,
    OcrQuality quality = OcrQuality.Fast,
    IReadOnlyList<string>? languages = null)
```

Contract:

1. Never throws. Empty list on any failure (null stream, decode fail,
   Vision error, exception).
2. Decode path: `NSData.FromStream(pngStream)` -> `CGImageSource.FromData`
   -> `CreateImage(0, CGImageOptions())`. So it always reads frame 0 of
   the encoded image.
3. Vision handler: `new VNImageRequestHandler(cg, new NSDictionary())`
   — empty options dict, no orientation override (assumes upright pixels).
4. Request config (per `OcrQuality`):
   - `RecognitionLevel` = `Fast` when quality is Fast (the DEFAULT),
     `Accurate` when quality is Accurate.
   - `UsesLanguageCorrection` = `(quality == Accurate)`. **Fast path
     disables language correction.**
   - `RecognitionLanguages` = caller's list OR the fallback array
     `["zh-Hans", "zh-Hant", "en-US"]` (order matters — Vision uses it
     as a priority hint).
   - No explicit revision pin. Everywhere lets Vision pick the current
     default revision (VNRecognizeTextRequestRevision3 on macOS 14+).
   - No explicit minimum-confidence filter. Confidence returned as-is
     on each `OcrLine`.
5. Perform: `handler.Perform([req], out var nsErr)`. **Synchronous**
   call — the completion handler passed to the request is a no-op
   `(rq, err) => {}`; results are pulled via `req.GetResults<...>()`
   after `Perform` returns.
6. Per observation:
   - `obs.TopCandidates(1)` — take top-1 only. Skip if empty.
   - `text = cands[0].String ?? string.Empty`.
   - `confidence = cands[0].Confidence` (0..1 float).
   - Bounding box: Vision returns `.BoundingBox` as a normalized rect
     with origin at LOWER-LEFT, axes 0..1.
   - Conversion:
     * `x = round(nx * imgW) + originPx.X`
     * `w = max(1, round(nw * imgW))`
     * `y = round((1.0 - ny - nh) * imgH) + originPx.Y`  (upper-left origin)
     * `h = max(1, round(nh * imgH))`
   - Rounded, then clamped to `>= 1` on width/height. Sub-pixel
     truncation would zero out thin glyphs.
7. Final: `lines.Sort((a, b) => a.Bounds.Y.CompareTo(b.Bounds.Y))`
   — sorted ascending by y (top-to-bottom on the upper-left origin).
8. Sync-vs-async: the C# API is synchronous. `handler.Perform` blocks
   until Vision returns.

## Swift Vision mapping

- `VNImageRequestHandler(cgImage:options:)` — options = `[:]`.
- `VNRecognizeTextRequest` — completion `{ _, _ in }` no-op.
- `.recognitionLevel = .fast` (matches default Fast).
- `.usesLanguageCorrection = false` (matches Fast path).
- `.recognitionLanguages = languages`.
- `try handler.perform([request])`.
- Results: `request.results as? [VNRecognizedTextObservation]`.
- `obs.topCandidates(1).first?.string` / `.confidence`.
- `obs.boundingBox` is `CGRect` normalized (0..1, lower-left).

## Public API deviations from Everywhere

Task-prescribed signature:

```swift
static func ocr(
    image: NSImage,
    languages: [String] = ["en-US", "zh-Hans"]
) async -> OCRResult?
```

Deltas:

1. Input is `NSImage`, not a PNG stream. NSImage yields a `CGImage`
   via `cgImage(forProposedRect:context:hints:)`.
2. No `originPx` — Swift-side bounding boxes are in image-local pixel
   space (origin at image top-left), NOT translated to screen
   coordinates. Callers who want screen coords add the origin
   themselves. This matches how `OCRCapture` is consumed within the
   context service (regions are cropped before OCR, so the caller
   already knows the region origin).
3. Default language list is `["en-US", "zh-Hans"]` — the OpenClicky
   product default (per docs row 16 English + Simplified Chinese). Not
   the Everywhere default (`zh-Hans, zh-Hant, en-US`). Callers can pass
   any list they need.
4. Quality is fixed to Fast (matches Everywhere's default). The
   Accurate branch is not exposed in the P1 signature. Adding a
   variant later is trivial — keep the internal switch structured for
   that expansion.
5. Return type is `OCRResult?` instead of `[OCRLine]`.
   - Success (including zero observations) -> `OCRResult(lines: [...])`.
   - Failure (image decode fails, Vision throws) -> `nil`.
   - This gives callers a clean "was OCR attempted" signal separate
     from "did OCR produce text". Everywhere collapses both to empty
     list; the Swift-side signal is a strict superset.
6. `async`: `VNImageRequestHandler.perform` is synchronous. The Swift
   API is `async` so we can hop the actual Vision call off the caller
   task via a detached task, keeping the main actor responsive.

## Bounding-box coordinate space

`OCRLine.bounds` is a `CGRect` in image-local pixel space, upper-left
origin, integer-rounded, width/height clamped to `>= 1`. Callers wanting
lower-left / normalized rects can transform trivially.

## Nil / error paths

- `image.cgImage(...)` returns nil -> return `nil`.
- `VNImageRequestHandler.perform(...)` throws -> return `nil`.
- `request.results` is nil or wrong type -> return
  `OCRResult(lines: [])` (Vision succeeded but yielded nothing).
- Observation without a top candidate -> skip that line, keep going.
