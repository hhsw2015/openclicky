## Fixes landed

### HIGH #1 — Structured progressDriven / completionMarker fields (F28 substrate)

- `HeyClickyChatToolCallClient.RouteParseResult`:
  - Added `progressDriven: Bool` (default `false`) and
    `completionMarker: String?` (default `nil`).
  - Decoder now reads snake_case JSON keys `progress_driven` /
    `completion_marker` from the `[ROUTE]` tag (with sane defaults when
    absent).
  - Added memberwise `init(...)` (with defaults for the two new fields)
    plus `effectiveCompletionMarker` helper. When `progressDriven=true`
    but marker absent, `effectiveCompletionMarker` returns the
    `AGENTS-longrun-template` convention `"LAST_COMPLETED: DONE"`. The
    raw value stays unmodified so `openclicky.route_parsed` logs
    exactly what the model said.
- `OpenClickyRouteDispatcher.dispatch()` + `spawnCodex()` thread the
  fields through to `CompanionManager.dispatchRoutedAgentTask`. Logs
  extended with `progress_driven` / `completion_marker` keys.
- `OpenClickyRouteDispatcher.composeAgentPrompt` now embeds
  `progress_driven: true` and the effective `completion_marker` into
  the codex agent's INITIAL SCENE CONTEXT block so the agent knows
  what marker it is expected to write.
- `CompanionManager.startVoiceAgentTaskPlan`,
  `startVoiceAgentTask`, `dispatchRoutedAgentTask` gained
  `projectRef: String?`, `slug: String?`, `progressDriven: Bool = false`,
  `completionMarker: String? = nil` params. Defaults preserve all
  existing call sites (7 call sites verified: 6147, 6863, 6884, 6911,
  6937, 6997, 10246, 11069, 11111, 11192, 11211 — none needed
  editing).
- `CodexAgentSession` gained four `@Published` fields:
  `progressDriven`, `completionMarker`, `routeProjectRef`, `routeSlug`.
  `CompanionManager.startVoiceAgentTask` sets them on the freshly
  minted session immediately after the workdir override guard.
- The F28 observer that reads `<workdir>/progress.md` and re-fires the
  turn is intentionally NOT wired here — the task brief calls that out
  as a separate landing (Task #203). All the surface state it will
  need is now present on the session.

Verification:

  returns **27** hits (was 0).
- `grep -rn "completionMarker\|completion_marker" cursor-buddy/*.swift`
  returns **23** hits (was 0).

### HIGH #2 — Tilde-expand route.workdir

Two sites:
- `OpenClickyRouteDispatcher.spawnCodex` — expands the raw
  `route.workdir` via `(raw as NSString).expandingTildeInPath` before
  the value is passed downstream.
- `CompanionManager.startVoiceAgentTask` — same expansion applied to
  `workingDirectoryOverride` before `FileManager.fileExists` is called.
  `FileManager.fileExists` does not expand `~`, so the previous code
  silently rejected `"~/Projects/foo"` and let the session default
  through.

### MEDIUM #1 — Sanitise model-supplied slug

`OpenClickyRouteDispatcher.spawnCodex` now runs `sanitizedSlug(from:)`
on any model-supplied `route.slug` before joining it into the
`EphemeralTasks/<slug>/` base. Also falls back to
`"task-<epoch>"` when the slug is empty rather than a raw UUID, matching
the classifier's own fallback shape.

### MEDIUM #2 — Anchor parseRouteJSON regex

`HeyClickyChatToolCallClient.parseRouteJSON` now tries an anchored
pattern first (`\[ROUTE\]\s*(\{[^\n]*\})\s*$` with
`.anchorsMatchLines`) so the trailing-line contract wins deterministically
even when the model self-quotes an example earlier in its reply. Falls
back to the previous loose scan taking `matches.last` if the anchored
match fails (preserves prior behaviour when the model does not append a
final newline).

### LOW #1 — Enforce confidence < 0.6 as ambiguous

`OpenClickyRouteDispatcher.dispatch()` now applies the design's 0.6
gate on the task branches (`short_task` / `long_task_new` /
`long_task_existing`). When the model self-reports confidence below
0.6, we log `openclicky.route_confidence_guard`, invoke
`classifyFallback`, and only spawn if the fallback returns a
task-shaped kind. `chat` / `ambiguous` short-circuit unchanged.

### LOW #2 — ProjectRegistry lookup when workdir empty

`OpenClickyRouteDispatcher.spawnCodex` resolves workdir in this order
now: explicit `route.workdir` (tilde-expanded) → `ProjectRegistry`
lookup on `route.projectRef` (score ≥ 0.75) → `preflight.selectedFolder`
→ ephemeral `EphemeralTasks/<sanitised-slug>/`. Logs
`openclicky.route_project_ref_resolved` when the registry hit fires.

### LOW #3 — Wire ROUTE directive block on other provider arms

Confirmed intentional (Fable is OpenClicky's own dialog model and the
sole `[ROUTE]` emitter — non-Fable arms are covered by the fallback
classifier's preflight-signal path). Added a header comment on the
`.heyclickyFree` case in
`CompanionManager+AIResponsePipeline.swift` explaining the scope
choice and pointing at the review note for the trade-off.
