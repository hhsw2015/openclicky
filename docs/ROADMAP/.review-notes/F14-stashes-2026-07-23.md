### AnnotationStash — Issues Found

- **HIGH #1**: `consume(_:)` notifies only when at least one item matched (`AnnotationStash.swift:187, 196-198`); Everywhere fires `Changed?.Invoke()` unconditionally for a non-empty batch (`AnnotationStash.cs:232`). Task description called this out and it is confirmed as a real behaviour divergence. Downstream UI observers relying on "Changed fires exactly when Consume runs with a batch" will not update on a stale/no-op consume in openclicky. → **Fix**: post `annotationStashDidChange` whenever `items.isEmpty == false`, matching Everywhere's unconditional invocation.

- **MEDIUM #2**: `RemoveItem(AnnotationItem)` (`AnnotationStash.cs:179-193`) is not ported. Everywhere's annotation overlay uses it to replace a previously-committed note (drop the exact instance, then re-add). Without it, openclicky callers that mirror the overlay flow have to fall back on `consume(_:)`, which as of Issue #1 also silently no-ops when the value has drifted. → **Fix**: implement `removeItem(_:)` that first-matches by value equality (Swift port's identity model) and fires the notification on hit.

- **MEDIUM #3**: `Remove(int index)` (`AnnotationStash.cs:195-209`) is not ported. Everywhere's caller uses index-based removal after inspecting `Peek()`. → **Fix**: implement `remove(at index: Int) -> Bool` with pre-prune and boundary check, matching `AnnotationStash.cs:200-208`.

- **LOW #4**: `consume(_:)` uses value equality (`firstIndex(where: { $0.item == target })`), Everywhere uses reference identity + descending iteration. Documented as intentional at `AnnotationStash.swift:174-181` (comment notes `capturedAt` makes items de-facto unique). Acceptable for the current LaunchPhrase / SnapshotContext caller set; flag only for anyone constructing synthetic duplicate `AnnotationItem` values in tests. → **Fix**: none required; keep documented divergence.

- **LOW #5**: Openclicky lacks the `Added(AnnotationItem)` event equivalent — no per-item payload is delivered on append. `annotationStashDidChange` is fire-only; observers must `peek()`. Documented at file header lines 24-29. → **Fix**: none required if callers already reconcile via `peek()`; otherwise expose the last-appended item via `userInfo`.

### WhiteboardStash — Issues Found

- **MEDIUM #1**: `clearWithEvent()` fires `openClickyWhiteboardStashCleared` even when `pendingRegions` is already nil but `imageBytesById` is non-empty (`WhiteboardStash.swift:195`). Everywhere gates the event on `_current is not null` only (`WhiteboardStash.cs:222`). A common sequence is `set()` → `take()` (regions consumed, image bytes still cached) → `clearWithEvent()`: openclicky fires the event here, Everywhere does not. If any subscriber uses the event to tear down region overlays it will double-fire or fire spuriously after the overlay is already gone. → **Fix**: change to `let hadPending = pendingRegions != nil` to match Everywhere.

- **LOW #2**: Openclicky ships only `clearWithEvent()`; no silent `Clear()` counterpart. Everywhere has both (`WhiteboardStash.cs:203-210` silent, `217-227` event-firing). Tests / shutdown paths that want to reset without firing observers have to swap the notification centre. → **Fix**: add `func clear()` mirroring `PickStash.clear()` and `AnnotationStash.clear()` for API symmetry.

- **LOW #3**: `Append()` is missing (documented as intentional at `WhiteboardStash.swift:28-32`). If a future overlay workflow adopts "continue session" the port needs this path. → **Fix**: none required for Phase 7 scope; keep documented divergence.

## Cross-cutting Findings

- **PASS**: All three stashes cite the Everywhere source in the file header at the correct pin (`PickStash.swift:1`, `AnnotationStash.swift:1`, `WhiteboardStash.swift:1`).
- **PASS**: All three use `NSLock` in place of Everywhere's `object lock` / `Lock _gate`.
- **PASS**: All three take an injectable clock (`clock: @escaping () -> Date`) matching Everywhere's `TimeProvider` dependency injection pattern.
- **PASS**: TTL expiry is silent on Peek/Take across all three — no notification fired for passive housekeeping. Matches Everywhere.
- **PASS**: All three post notifications AFTER releasing the lock, avoiding observer-under-lock deadlock risk.
- **DIVERGENCE (intentional, documented)**: Everywhere's separate `Pinned` / `Cleared` / `Added` / `Changed` / `Drawn` events are collapsed into a single `didChange`-style notification per stash. Documented in each file header.

## Verdict

- [ ] BYTE_MATCH
- [ ] SEMANTIC_MATCH — logic identical, some Swift idiomatic reshaping OK
- [x] DIVERGENT — has intentional deviations documented in file header, **plus** two unintentional bugs (AnnotationStash #1 unconditional-vs-conditional consume notification; WhiteboardStash #1 clearWithEvent firing on image-bytes-only) and two missing APIs (AnnotationStash `RemoveItem` / `Remove(index)`).
- [ ] BROKEN

Practical assessment: **DIVERGENT**. The intentional deviations are all clearly labelled in file headers. The two unintentional divergences are observable but low-impact for the current caller set — worth fixing before shipping to keep parity with Everywhere's contract, especially the AnnotationStash `Consume` notification behaviour since UI code depends on it.

## Recommendations

Prioritised fix list:
1. **AnnotationStash Issue #1** — post `annotationStashDidChange` unconditionally when `consume(_:)` is called with a non-empty batch. Matches `AnnotationStash.cs:232`. One-line change.
2. **WhiteboardStash Issue #1** — gate `clearWithEvent()` on `pendingRegions != nil` only, not on the image side-table. Matches `WhiteboardStash.cs:222`. One-line change.
3. **AnnotationStash Issue #2 + #3** — port `removeItem(_:)` and `remove(at:)` to close the API gap. Small, mechanical.
4. **WhiteboardStash Issue #2** — add silent `clear()` for API symmetry with `PickStash.clear()` / `AnnotationStash.clear()`.
5. (Optional, cosmetic) Document the "no `Added(AnnotationItem)` payload" in the annotation stash observer contract so downstream UI code knows to peek() rather than wait for a per-item event.
