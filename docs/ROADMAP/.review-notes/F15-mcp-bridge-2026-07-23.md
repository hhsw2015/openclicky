## Issues

### Issue 1 (HIGH) — 43-tool assertion is stale; runtime is 49
The task description claims "openclicky 43 = 22 core + 8 memory + 7 doc + 6 meta". Actual counts from `OpenClickyExternalControlBridge.swift:1652-1707` + `:2325`:
- 22 "core" (Layer 0 + Phase 5), 7 doc, 8 memory, 6 meta = 43 in the `sensorToolNames` set literal.
- **Plus 6 connector tools** appended via `OpenClickyConnectorBridgeTools.descriptorsRaw` at `:2325`.
- Grand total via the descriptor pipeline = 49. `Self.sensorToolDescriptorsRaw.count` (line 1825 pipeline) = 49; `Self.sensorToolNames.count` (line 1652 set) = 43. These two are out of sync.

Consequence: `sensor_health.capture_count = sensorToolNames.count` reports 43 (`:2423`), but the actual tools/list surfaces 49 tools (43 native + 6 connector via `+` at `:2325`). `sensor_health` under-reports by 6.

Verify: `sensorToolNames.contains(name)` in `handleSensorRequest` (line 2367) uses the 43-name set as the auth gate — meaning **connector_* tool calls should be rejected** at `/mcp/sensor` even though they appear in `tools/list`. Not verified end-to-end here; worth a runtime probe.

### Issue 2 (MEDIUM) — Meta domain roster diverges from Everywhere's `TierGate.Domains`
Everywhere `TierGate.Domains` uses `browser_core / web_analysis / memory / gates / generator / …` (`TierGate.cs:13-55`). Openclicky `OpenClickyMetaDomain.all` = `core, browser, terminal, finder, whiteboard, doc_readers, web, memory, orchestrate` (`OpenClickyMetaTools.swift:85-89`). Only `memory` and `web` match by name; `core` maps conceptually to Everywhere's `SearchTierTools` (which is not a `Domains` key). This is intentional per file header comment (`OpenClickyMetaTools.swift:63-67` — "aligned to the openclicky sensor surface"), but Everywhere clients relying on domain names cannot round-trip through `activate_domain` with the same argument.

### Issue 3 (LOW) — `sensor_health.version = "phase1"` is stale
`OpenClickyExternalControlBridge.swift:2424` reports `"version":"phase1"` while the roadmap has advanced through Phase 5 Layer 0 additions, Phase 2 v2 doc/memory/meta batches, and Phase 7.5 connectors. Cosmetic only.

### Issue 4 (LOW) — `initialize.serverInfo.version` hard-coded `"1.0.0"`
`OpenClickyExternalControlBridge.swift:2340` returns constant `"1.0.0"`. Everywhere sources its version from `typeof(EverywhereMcpHttpHost).Assembly.GetName().Version` (`EverywhereMcpHttpHost.cs:299`). Not a client-breaking issue.

### Issue 5 (LOW) — `Access-Control-Allow-Origin: http://127.0.0.1` is hard-coded and port-agnostic
`OpenClickyExternalControlBridge.swift:809,828` emits literal `http://127.0.0.1` (no port). Everywhere `IsAllowedOrigin` (`EverywhereMcpHttpHost.cs:463-478`) whitelists `localhost / 127.0.0.1 / [::1]` on the bound port only. Openclicky's response header is looser than Everywhere's request filter, but the loopback-bind and `hasValidBridgeToken` gate make the practical attack surface bounded.

### Issue 6 (INFO) — `sensor_health` returns `capture_count`, not `{"status":"ok","capture_count":43}` byte-match
Task verification asks for `{status:ok, capture_count:43}`. Actual return (`:2420-2426`): `{"status":"ok","capture_count":<sensorToolNames.count>,"version":"phase1"}`. Extra `version` field, and `capture_count` is dynamic (currently 43 per `sensorToolNames`), not the constant 43.

## Verdict

**PASS with caveats.** Transport shape (Streamable HTTP SSE + chunked encoding + `Mcp-Session-Id` + 202 on `notifications/initialized`), envelope shape (`{content:[{type:text,text:...}],isError:bool}`), descriptor shape (`{name,description,inputSchema:{type,properties,required}}`), domain gate (`core` visible, hidden domains behind `activate_domain` + `OPENCLICKY_MCP_FULL=1` bypass), and auth (loopback + bearer) all match Everywhere semantics where a match applies. openclicky is intentionally a **subset** of the 96-tool Everywhere surface (37 shared, 12 openclicky-only, 59 not ported) and adds its own `x-openclicky-token` header and `:32123` default port.

Blocking issues: none. Should-fix before shipping: Issue 1 (stale 43 claim vs 49-tool reality + `capture_count` under-report) and Issue 2 (domain roster divergence). Issues 3-6 are cosmetic.
