## 4. Sort order

MacVisionOcrEngine.cs:106:
```csharp
lines.Sort((a, b) => a.Bounds.Y.CompareTo(b.Bounds.Y));
```

openclicky (line 155):
```swift
lines.sort { $0.bounds.origin.y < $1.bounds.origin.y }
```

Both ascending y, upper-left origin → top-to-bottom. Stability: `List<T>.Sort` in .NET is not stable; Swift's `sort(by:)` is guaranteed unstable as well (uses TimSort internally in recent Swifts, actually stable, but the contract is unspecified). Practically equivalent for observations that never share exact rounded y. **Verdict:** match.

## 5. `originPx` argument removed

Everywhere's `Recognize(Stream pngStream, PixelPoint originPx, ...)` translates all bounding boxes by `originPx` so the caller receives screen-pixel coords. openclicky's `ocr(image:languages:)` (line 58) drops `originPx` — bounds are returned in image-local pixel space. This is explicitly documented in the file header (lines 12-15) and in `OCRLine` doc (CaptureTypes.swift:1166-1172). The math change is exactly: remove the `+ originPx.X` / `+ originPx.Y` terms, which the port does.

**Verdict:** Documented signature diff. Correct implementation.
