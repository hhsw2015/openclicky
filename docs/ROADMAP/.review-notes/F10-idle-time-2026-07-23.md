### 3. `eventType` = "any input event" sentinel - PASS
- openclicky: `IdleTimeCapture.swift:40-46` constructs `CGEventType(rawValue: ~0)!`. Force-unwrap safe (Swift raw-value init accepts any `UInt32` bit pattern for `CGEventType`).

### 4. Return type `TimeInterval`, nil on negative - PASS
- openclicky: `IdleTimeCapture.swift:59` signature returns `IdleTimeInfo?`. Body at 64-67 returns `nil` when `seconds < 0`, else `IdleTimeInfo(seconds: seconds)`. `IdleTimeInfo.seconds` is `TimeInterval` (`CaptureTypes.swift:337`).
- Everywhere returns `double` and coalesces the exception path to `0` (`MacIdleTimeReader.cs:21-24`). Never surfaces negative because P/Invoke does not signal it.
- Divergence documented at openclicky `IdleTimeCapture.swift:16-25` and `CaptureTypes.swift:330-337`: Everywhere collapses errors to `0`; openclicky wraps success in `IdleTimeInfo` and returns `nil` on the CoreGraphics-documented "invalid" negative reading. Zero readings are valid successes on both sides.

## Findings
1. All four checklist items pass. 1:1 semantic port with a deliberate, in-source-documented divergence for the error signal (`nil` vs `0`).
2. `CGEventType(rawValue: ~0)!` force-unwrap is safe by construction; no fragility.
3. No unnecessary CFRelease / retain-count concerns since `CGEventSource.secondsSinceLastEventType` is a Swift-bridged static function, not a `+1` producer.

## Verdict

F10 accepted. Semantic parity with Everywhere's `MacIdleTimeReader`; the `nil`-on-negative deviation is documented at both the capture and type layer, and callers wanting Everywhere's exact numeric shape can use `capture()?.seconds ?? 0`.
