## Checklist verification

### 1. Both `AXManualAccessibility` + `AXEnhancedUserInterface` fired per pid - PASS
- openclicky constants (`AXQuirksInstaller.swift:125,128`): `"AXManualAccessibility"`, `"AXEnhancedUserInterface"`. Byte-identical to Everywhere `AXAttributeConstants.cs:30-31`.
- `installIfNeeded` (lines 191-200) fires manual first, then enhanced. Order matches Everywhere `VisualElementContext.cs:127-128`.

### 2. `AXUIElementSetAttributeValue` with `CFBoolean` singleton - PASS
- openclicky `setBoolAttribute` (lines 247-272): `AXUIElementCreateApplication(pid)` -> `kCFBooleanTrue`/`kCFBooleanFalse` -> `AXUIElementSetAttributeValue(app, attr as CFString, cfBool)`.
- Everywhere `SetAppBoolAttribute` (`AXUIElement.cs:1186-1203`): identical shape; uses `GetCFBooleanTrue()`/`GetCFBooleanFalse()` singletons (lines 1193, 1205-1214).
- CFBoolean-singleton requirement documented in both files: openclicky lines 234-241, Everywhere lines 1178-1184.
- Ownership: `AXUIElementCreateApplication` returns `+1`-retained; Swift ARC releases on scope exit. Explicit `CFRelease` unnecessary. Documented at lines 242-246.

### 3. Idempotent via `Set<Int32>` + `NSLock` - PASS
- Storage: `private static var installedPids: Set<Int32>` (line 141).
- Lock: `private static let lock = NSLock()` (line 136).
- Fast path (lines 177-182): lock, `contains`, unlock, early-return on hit.
- Successful-install commit (lines 202-206): lock, `insert`, unlock. Only path that mutates the set.
- Contrast with Everywhere `AppResolver.cs:25-28`: `_a11yEnabledPids.TryAdd(pid, true)` inserts BEFORE the AX call, so a failing install poisons the cache. openclicky's split (check first, then insert only after both attributes land) is a deliberate strengthening of the contract; documented at lines 173-176, 189-190, 202-203.
- Verified by test `test_installIfNeeded_failedInstallIsNotCached` (`AXQuirksInstallerTests.swift:161-183`).

### 4. Both-attributes-or-nothing contract - PASS (throw-on-first-failure)
- Sequential `try` calls (lines 191-200): if manual throws, enhanced is never attempted and pid is not cached. If manual succeeds but enhanced throws, pid still not cached (line 204 only reached after both).
- Diverges from Everywhere's `return manualOk || enhancedOk` at `VisualElementContext.cs:129` which accepts partial success. openclicky's stricter AND-contract documented at file header lines 46-53 and body lines 188-190.

### 5. Success gate: `.success || .noValue` (widened vs Everywhere) - PASS
- openclicky (line 269): `if status != .success && status != .noValue { throw ... }`.
- Everywhere (`AXUIElement.cs:1197`): `return err == AXError.Success;`.
- Widening documented at openclicky lines 264-268: `.success` is the exact Everywhere match; `.noValue` is the intentional openclicky alias to avoid spurious throws when the target app has not preloaded the private attribute name. Verified as intentional divergence.

### 6. 1500 ms bounded-wait lives at CALLER level, NOT in installer - PASS
- openclicky installer: `installIfNeeded` is synchronous with no timeout wrapper. File header lines 54-60 and doc-comment lines 161-167 both instruct callers to wrap the call in their own `Task { try? ... }` + timeout.
- Everywhere: 1500 ms `task.Wait(TimeSpan.FromMilliseconds(1500))` lives at `AppResolver.cs:44-52` (i.e. `EnsureA11yEnabledOnce` caller-side helper), NOT inside `SetAppBoolAttribute` at `AXUIElement.cs:1186-1203`.
- Placement matches Everywhere exactly. openclicky's file-header comment (lines 54-60) references `AppResolver.EnsureA11yEnabledOnce` L31-42 - line numbers align with the actual Everywhere source (25-53).

### 7. Error model - PASS
- `AXQuirksError` (lines 79-108): `.invalidPid(Int32)` for `pid <= 0`, `.setAttributeFailed(status: Int32)` carrying `AXError.rawValue` for AX failures. Equatable conformance explicit (lines 98-107).
- `pid > 0` guard in both `installIfNeeded` (line 169-171) and `setBoolAttribute` (line 252-254).
- Everywhere returns `bool false` for `pid <= 0` (`AXUIElement.cs:1188`); openclicky promotes this to a thrown `.invalidPid` so callers can distinguish it from an AX-layer failure. Documented lines 81-85.

### 8. Public attribute constants - PASS
`AXQuirksInstaller.manualAccessibility` and `.enhancedUserInterface` (lines 125, 128) are `public static let`. Byte-checked in `test_attributeConstants_matchEverywhere` (`AXQuirksInstallerTests.swift:36-40`).

## Findings
1. All eight checklist items pass. The port is stricter than Everywhere in exactly two documented places (all-or-nothing install, cache-only-on-success), and looser in one (`.noValue` accepted alongside `.success`). Every divergence has an in-source rationale.
2. `NSLock` fast-path releases before `try` calls (lines 177-179), so a throwing AX call cannot deadlock the cache.
3. `AXUIElementCreateApplication` result is not nil-checked; the return type is non-optional in Swift's bridged signature, matching Everywhere's `if (appHandle == 0) return false` guard which openclicky elides since the Swift bridging cannot yield a null CFTypeRef here.
4. Comment/doc block for `installIfNeeded` at lines 143-167 is partially garbled in the source (missing prose fragments after line 145 markers). Content is present but formatting is broken relative to the sibling `setBoolAttribute` doc. Cosmetic only; no code impact.

## Verdict

F12 accepted. Byte-matched attribute strings, correct ordering, CFBoolean-singleton usage, ARC-safe ownership, idempotent `Set<Int32>+NSLock` cache, cache-only-on-full-success, `.success || .noValue` success gate (intentional widening), and 1500 ms bounded-wait correctly placed at caller level per Everywhere's own layout. One cosmetic doc-formatting glitch in the `installIfNeeded` header block; no runtime impact.
