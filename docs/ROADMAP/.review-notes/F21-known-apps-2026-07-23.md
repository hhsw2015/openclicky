## Issues

1. **Discovery pipeline missing (blocker for F21).** `Packages/OpenClickyContextService/.../OpenClickyContextSnapshotPayload.swift:282-286` still carries the Phase-7 TODO with `discoveryUrl = nil, statePath = nil`. Without `resolveDiscoveryUrl` and `toStatePath` in the writer, the `[openclicky-discover]` branch (`:301-306`) is unreachable regardless of what the user configures in `knownApps`. The settings-side type and default seed exist, but nothing consumes them. Fix: port `ContextStashWriter.cs:743-791` into the Swift writer (or the payload formatter's caller), inject the resolved `discoveryUrl` / `statePath` into `formatForHook`, and thread `OpenClickyContextAwarenessSettings.shared.knownApps` into that resolver.

2. **Rebrand of `xlb-style` copy.** Line format matches byte-for-byte except `"xlb-style local app self-describes at"` was renamed to `"openclicky-style local app self-describes at"` (`OpenClickyContextSnapshotPayload.swift:302` vs `ContextStashWriter.cs:723`). This is a deliberate rebrand consistent with the `[openclicky-*]` prefix changes, but the prompt asks for "byte-for-byte" line format parity. If downstream hook tooling greps on `"xlb-style"` this diverges; if it greps on the bracket prefix it's fine.

3. **100ms `RegexMatchTimeoutException` guard missing.** Even once the resolver is ported, Swift's `NSRegularExpression` has no built-in timeout the way .NET's `Regex.IsMatch(..., timeout)` does (`ContextStashWriter.cs:775-778`). ReDoS protection must be re-implemented (dispatch-queue watchdog or precompiled-with-anchor pattern rejection) to preserve behaviour.

4. **`OpenClickyKnownApp` type lives outside `OpenClickyContextService`.** `cursor-buddy/OpenClickyContextAwarenessSettings.swift:142-154` declares the type inside the app target. `Types/CaptureTypes.swift` (grep `KnownApp` → 0 hits) does not export it, so the package-side writer cannot reference `OpenClickyKnownApp` when ported. Prompt claim "Types/CaptureTypes.swift: OpenClickyKnownApp" is not backed by code.

5. **Sentinel not consulted for KnownApps.** `OpenClickyContextAwarenessSettings.swift:391-399` seeds `knownApps` whenever the UserDefaults key is absent — regardless of `alreadySeeded`. A user who deliberately clears the row and the app writes `[]` back at `:322-325`; subsequent launches read the `[]` (data key still present) and don't re-seed. But if UserDefaults gets wiped (`defaults delete com.jkneen.openclicky openclicky.contextAwareness.knownApps` only), the row re-populates even if the sentinel says "seeded once". The other seven fields follow the same pattern, so this is a small consistency note rather than a divergence from the prompt's "one-shot seed, respects cleared bindings on re-launch" — clearing writes `[]`, which persists.

## Verdict

**Not ready.** The KnownApps *storage* side (type, default seed, sentinel gating, JSON persistence, Reset method) is in place and matches Everywhere's user settings byte-for-byte. The *consumer* side is not wired: the writer still hard-codes `discoveryUrl = nil, statePath = nil` at `OpenClickyContextSnapshotPayload.swift:285-286`, so the `[openclicky-discover]` hint never fires. Blockers for F21:

- Port `ResolveDiscoveryUrl` (`ContextStashWriter.cs:756-791`) into Swift with a real ReDoS mitigation.
- Port `ToStatePath` (`ContextStashWriter.cs:743-751`) into Swift.
- Thread `OpenClickyContextAwarenessSettings.shared.knownApps` into the writer or payload builder so `formatForHook` receives non-nil values on a title match.
- Optionally hoist `OpenClickyKnownApp` into `OpenClickyContextService` so both sides share the same type.
