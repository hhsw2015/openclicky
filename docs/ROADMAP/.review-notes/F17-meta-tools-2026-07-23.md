## Issues Found

- **HIGH** — StrategyNote G7 mutation-verb guard uses substring `.uppercased().contains("POST"/"PUT"/"DELETE"/"PATCH")` (`OpenClickyMetaTools.swift:437-441`) instead of Everywhere's `\b(POST|PUT|DELETE|PATCH)\b` regex (`GateTools.cs:47-49`). Evidence like `"POSTAL address unchanged"`, `"REPUTATIONAL risk"`, `"PATCHY signal quality"`, `"COMPUTED signature"`, `"OUTPUT bytes 32K"` will false-flag as mutation verb and throw `MUTATION_UNAPPROVED`. Fix: switch to a regex with word boundaries or split on non-alphanumeric characters and require whole-token match.

- **MEDIUM** — Registry duplicate-register double-indexes BM25 (`OpenClickyMetaTools.swift:254-261`). When `register(_ descriptor)` is called for an already-known `descriptor.name`, the code overwrites the descriptor dict entry but calls `index.add(descriptor)` unconditionally, appending a second Doc row into the BM25 store while the old row stays. Score-inflation for re-registered tools; `docs.count` drifts above the visible tool count. Fix: guard `index.add(...)` with the `descriptors[descriptor.name] == nil` check (only add on first insert), or track a `Bool` for whether a re-index rebuild is needed.

- **MEDIUM** — Domain roster does not match Everywhere. `TierGate.cs:13-55` uses `browser_core / web_analysis / memory / gates / generator / …` (the binary read was partial but the visible names above confirm this). Openclicky uses a re-aligned nine-name roster (`core / browser / terminal / finder / whiteboard / doc_readers / web / memory / orchestrate`). The reviewer prompt's "Enumeration: core, browser, terminal, finder, whiteboard, doc_readers, web, memory, orchestrate (9)" is the openclicky roster, NOT Everywhere's. Header at `OpenClickyMetaTools.swift:64-67` documents this as intentional. Callers cross-referencing Everywhere activation names ("activate_domain observation") will fail because openclicky has no alias table and no `browser_core` name. Confirm with SPEC owner whether re-aligned domains are the intended shape; if yes, add a DomainAliases table (parity with `SessionActivations.cs:28`) so cross-fleet MCP clients written against Everywhere naming still work.

- **MEDIUM** — `SessionActivations` supports `"full"` as an all-domains override (`SessionActivations.cs:39`); openclicky has no `"full"` handling. `activateDomain("full")` returns `false` because `OpenClickyMetaDomain.all` does not include it (`OpenClickyMetaTools.swift:305-313`). Fix: accept `"full"` in `activateDomain` and treat it in `activatedDomains()` / `listDomains()` as making every domain active.

- **MEDIUM** — `BatchTool` in Everywhere hard-restricts allowed tool prefixes to `browser_` (OpenDia forwarded) and `everywhere.` (stub) — anything else is rejected with `"missing browser_ / everywhere. prefix"` (`BatchTool.cs:71-88`). Openclicky's `batch()` dispatches ANY registered tool via `MetaToolDispatchDelegate` (`OpenClickyMetaTools.swift:391-393`). This is a superset — arguably more useful — but is not byte-parity. If the intent is parity, add a prefix allowlist gate.

- **LOW** — `readPick.auto` mode always resolves to `"full"` (`OpenClickyStashTools.swift:253-254`), losing Everywhere's hyperlink-density heuristic (`ReadPickTool.cs:114-124`). Documented as intentional in the file header but downstream token-savings vanish. If skill authors relied on `auto → links` for xlb popups, the token cost will regress on the port.

- **LOW** — `picked_index` wire field carries a STRING (mode name) in openclicky (`OpenClickyStashTools.swift:87-88`), an INT (node index) in Everywhere. Wire-shape mismatch documented at `CaptureTypes.swift:2353-2358` as intentional. Any test fixture doing `assert result.picked_index == 0` will now fail because it sees `"full"`.

- **LOW** — `readWhiteboard` header hard-codes `"1 leaf"` and omits confidence + image-count segments (`OpenClickyStashTools.swift:355`). Everywhere emits real leaf count, singular/plural, optional image counts, and `confidence X.XX` (`ReadWhiteboardTool.cs:44-49`). Header schema not parseable by downstream matchers written against Everywhere.

- **LOW** — `readWhiteboard.drawn:false` returns `markdown: ""` (`OpenClickyStashTools.swift:210`); Everywhere returns `markdown: null` (`ReadWhiteboardTool.cs:34`). Consumers checking `markdown != null` see truthy on empty read.

- **LOW** — `MetaToolCoreToolGate` / `SelfExpandGate` re-read env vars on every access; Everywhere caches with `Lazy<bool>`. Documented as intentional for tests. Prod effect nil but adds per-call `ProcessInfo.environment[]` dictionary hit.

- **LOW** — Batch loop has no `CancellationToken` equivalent (`OpenClickyMetaTools.swift:387-411`); Everywhere's loop honors `ct.ThrowIfCancellationRequested()` (`BatchTool.cs:56`). Under Swift structured concurrency the outer Task cancel would still stop the pending await, but individual step-boundary checks are missing.

- **LOW** — BM25 deterministic tie-break by insertion index (`OpenClickyMetaTools.swift:164-168`) added on top of Everywhere behavior — negligible for real queries but changes wire output when multiple docs tie on score. Not a bug, but not byte-match.

## Verdict

- [ ] BYTE_MATCH
- [ ] SEMANTIC_MATCH
- [x] DIVERGENT — intentional deviations documented in file headers (domain roster, `readPick` auto/mode, `picked_index` type, whiteboard header shape, UUID-vs-string image id, envelope shape at bridge boundary).
- [ ] BROKEN — with one HIGH exception, see below.

The G7 mutation-verb guard is a **real bug** (substring vs word-boundary) and needs a fix before ship. The duplicate BM25 registration is a **real bug** but only surfaces when `register(...)` is called with the same descriptor name twice, which the current bridge bootstrap likely doesn't do. Both are addressable in localized edits.

Everything else on this file is either byte-match with Everywhere (BM25 core math, gate env-var semantics, StrategyNote schema + ordering, AnnotationSource enum, whiteboard kind labels, batch sequential + stop-on-error) or an intentional documented deviation (domain roster, snapshot-based readPick, UUID image ids, non-throwing addAnnotation shape).

## Recommendations

Prioritized fix list:

1. **G7 mutation-verb guard** (`OpenClickyMetaTools.swift:433-444`): replace substring `.contains(verb)` with token-boundary matching. Minimal fix — split evidence on non-alphanumeric, uppercase-compare each token to the four verbs.

2. **BM25 duplicate register** (`OpenClickyMetaTools.swift:254-261`): move `index.add(descriptor)` inside the `if descriptors[descriptor.name] == nil` branch so re-registrations don't double-index, OR add a rebuild path if descriptor overwrites are expected.

3. **`"full"` domain support** (`OpenClickyMetaTools.swift:305-323`): accept `"full"` in `activateDomain`, treat as all-domain-on in `activatedDomains()` / `listDomains()`. Optional if the openclicky sensor bridge never exposes `activate_domain("full")`.

4. **Domain alias table** (parity with `SessionActivations.cs:28`): if cross-fleet MCP clients target Everywhere-named domains, ship a static alias map (`observation → browser` / `browser_core → browser` / etc.) and consult it in `activateDomain`.

5. **BatchTool prefix gate** (`OpenClickyMetaTools.swift:387-411`): decide whether openclicky's batch should keep the "any registered tool" shape or restrict to a prefix allowlist for parity. If keeping the superset, document explicitly at the file header.

6. Consider adding `"full"` / `"disable"` env-var test overrides on the gate structs to reduce the per-call env dict hit; low priority.
