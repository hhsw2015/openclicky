## Issues

### Issue 1 (HIGH) — `memory_snapshot` semantics inverted vs Everywhere
Everywhere `memory_snapshot(site, cmd, content)` is a **write** verb: it persists sanitised capture bodies into `sites/<site>/fixtures/<cmd>-<iso>.json` with 5-copy rotation (`MemoryTools.cs:162-175`, `MemoryStore.cs:197-215`). Openclicky `memory_snapshot()` is a **read** verb returning the entire in-memory store dump (`OpenClickyMemoryTools.swift:94-96`). Same wire name, different action. Callers migrated from Everywhere expecting `memory_snapshot(site, cmd, content)` to write will get a schema-validation error at the bridge; callers doing openclicky-style `memory_snapshot()` reads won't work on Everywhere. Recommend either (a) rename to `memory_dump` or (b) split into `memory_snapshot_write` / `memory_snapshot_read`. Note however the doc-comment in `OpenClickyMemoryTools.swift:90-96` explicitly acknowledges this deviation — so this is documented intent, not accident.

### Issue 2 (MEDIUM) — `memory_freshness` return shape differs
Everywhere returns `{"freshness":"fresh"|"stale"|"cold"}` string. Openclicky returns `{"lastWriteAt": <ms>, "stalenessSeconds": <sec>}` numeric. Any downstream that keys on `.freshness` will break. `MemoryFreshnessInfo` has no field named `freshness` (`CaptureTypes.swift:2294-2302`).

### Issue 3 (LOW) — `MemoryEntry` is dead code
`CaptureTypes.swift:2257-2265` declares `struct MemoryEntry {key, value}` but no reference elsewhere in `Packages/OpenClickyContextService/Sources/OpenClickyContextService/Memory/` or the bridge. Confirmed via inspection of `MemoryStore.swift` and `OpenClickyMemoryTools.swift`. Either wire it into `memory_write_field_map` (Everywhere ports would call it `FieldMapEntry`) or delete.

### Issue 4 (LOW) — MERGE_CONFLICT payload drops SHA-256 hash
Everywhere `MergeConflictException(path, existingHash)` `MergeSafeWriter.cs:70-75` supplies SHA-256 of existing entry so callers can decide whether their overwrite is redundant. Openclicky `MemoryStoreError.mergeConflict(path:)` `MemoryStore.swift:23` carries only the path. `memoryErrorMessage(error)` (bridge) surfaces only path text. Callers who depend on `existing_hash` in the error envelope (`MemoryTools.cs:97`) won't get it.

### Issue 5 (LOW) — `MEMORY_LOCK_TIMEOUT` not achievable
Everywhere throws `MemoryLockTimeoutException` after 5s on the `.lock` sentinel `MergeSafeWriter.cs:63-68`. Openclicky uses in-process `NSLock` — cannot time out, cross-process contention not detected. Acceptable given the single-process design comment, but any wire-level parity test that expects `MEMORY_LOCK_TIMEOUT` from openclicky will always fail.

### Issue 6 (LOW) — Global `notes` field-map absent in Everywhere
Openclicky adds `MemorySnapshot.notes: [String]` (global notes list, `CaptureTypes.swift:2272`) plus `memory_append_note(text, endpoint?)` where `endpoint == nil` appends there. Everywhere has no equivalent — `AppendNote` always requires a site (`MemoryStore.cs:154`). Additive, safe.

### Issue 7 (LOW) — `WhenWritingNull` not replicated
Everywhere `JsonSerializerOptions.DefaultIgnoreCondition = WhenWritingNull` drops null fields from disk `MemoryStore.cs:21`. Openclicky uses default `JSONEncoder` (`MemoryStore.swift:210-211`) — every field emitted, including zero `lastWriteAt` and empty arrays. Files are larger and slightly harder to diff, but functionally identical after decode.

### Issue 8 (INFO) — Persistence path confirmed different
Task hint "Everywhere uses different path — verify" is correct:
- Everywhere: `~/.everywhere/sites/<domain>/{endpoints.json,field-map.json,notes.md,verify/*.json,fixtures/*.json,metadata.json}` — see `MemoryStore.cs:60,84,107,136,156,174,201` combined with `EverywherePaths.SitesDir()` referenced at `MemoryStore.cs:44`.
- Openclicky: `~/Library/Application Support/OpenClicky/memory.json` — single blob (`MemoryStore.swift:65-81`).

## Verdict

**PASS as a single-tenant reinterpretation, NOT as a byte-for-byte port.** The 8 wire names are preserved and the MERGE_CONFLICT + force-flag semantics carry over on the three write paths (endpoint, field-map per-key, verify-fixture). Atomic write via `Darwin.rename` is semantically equivalent to `File.Move(overwrite:true)`. NSLock replaces `SemaphoreSlim`-style single-writer serialisation within one process.

However, **argument shapes diverge on every one of the 8 tools** and two tools have materially different return shapes (`memory_snapshot` — write→read inversion, `memory_freshness` — string→numeric). This is intentional per the file-header comments (`OpenClickyMemoryTools.swift:1-7`, `MemoryStore.swift:1-13`) but any downstream code that expected wire-level parity will need porting. Task's "byte-match" claim on tool signatures is **not** upheld; only tool **names** match.

Blocking issues: none if the divergence is understood as intended. Should-address before external MCP clients arrive: Issue 1 (`memory_snapshot` verb inversion) and Issue 2 (`memory_freshness` shape). Issues 3-7 are cosmetic or belong-to-cleanup.
