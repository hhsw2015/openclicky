### 1. ClipboardReader `public.utf8-plain-text` type match - PASS

### 2. ClipboardWriter `declareTypes:owner:` invariant - PASS (delegated to AppKit)
- Everywhere `MacClipboardWriter.cs:29-32` manually calls `declareTypes:owner:` before `setString:forType:` because Objective-C `setString:forType:` returns NO if types were not declared.
- openclicky uses AppKit's `NSPasteboard.setString(_:forType:)` at `ClipboardWriter.swift:82` which handles the declare-types step internally. Documented at file lines 25-33 and 71-76.
- `clearContents()` at line 77 bumps changeCount (matches Everywhere line 27).
- Return value: openclicky surfaces the `Bool` from `setString`; Everywhere silently no-ops. Documented divergence at CaptureTypes.swift:2313-2317.

### 4. Divergences from Everywhere (documented in-source)

- `ok`/`bytes` fields on `ClipboardWriteResult` vs Everywhere's `{ ok, bytes = text.Length }`. `bytes` in openclicky is true UTF-8 byte count (`text.utf8.count`, ClipboardWriter.swift:92) not UTF-16 code units. Documented CaptureTypes.swift:2308-2311, ClipboardWriter.swift:88-93.
- `simulatePaste`/`simulateCopy` are openclicky extensions. Everywhere's `clipboard_paste` (`ClipboardTools.cs:42-46`) is an alias for `clipboard_read`; `clipboard_copy` (`ClipboardTools.cs:54-58`) aliases `clipboard_write`. openclicky drives real keystrokes so the active document participates. Documented ClipboardWriter.swift:14-23 and 41-45.

### 5. Type surface
`ClipboardInfo` (CaptureTypes.swift:278-317) widens Everywhere's `string?` return into a struct with P1 stubs (`filePaths`, `imageData`, `rtfData`). P0 field `text` matches Everywhere semantics 1:1. P1 fields always nil today; TODO markers present at 292-304 and in `ClipboardCapture.swift:65-67`.

`ClipboardWriteResult` (CaptureTypes.swift:2312-2327) mirrors `{ok, bytes}`.
